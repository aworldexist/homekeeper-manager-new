# 家物管家 · 家庭物品智能管理助手

可运行的中文家庭物品管理 Web Demo。React 19 + TypeScript + Vite，Lucide 图标；纯前端，本地规则演示，无账号、API Key 或运行时外部服务依赖。

## 交付内容

- `src/`：完整页面、组件、库存规则、智能录入、食谱、日期估算及提醒源码。
- `tests/`：库存、日期、解析、食谱、单位换算、持久化和提醒回归测试。
- `public/references/food-storage.xlsx`：用户提供的原始参考工作簿副本，未修改内容。
- `src/referenceWorkbook.json`：保留工作表、行号和原文的提取数据，6 张表共 54 行参考记录。
- `package.json` 与 `package-lock.json`：可安装的依赖清单及锁定版本。
- `requirement.tst`：按用户指定文件名提供的人类可读依赖说明。
- `deploy/nginx.conf.example`：静态部署配置示例。
- `dist/`：已构建的网页，可直接交给静态网站服务托管。
- `scripts/`：可选的 Excel 重新提取与源码打包辅助脚本。
- `DELIVERY_VERIFICATION.md`：本轮验收结果。

下载 ZIP 解压后，先进入 `homekeeper/` 目录，再执行下方命令。压缩包不包含 node_modules、浏览器私有数据、缓存或密钥。

## 环境与安装

需要 Node.js 20.19+ 或 22.12+，以及随 Node.js 安装的 npm。开发验收使用 Node.js 24。

```sh
npm ci
npm run dev -- --port 5173
```

访问 http://localhost:5173/ 。依赖已安装时可直接运行第二条命令。

这是 Node.js 项目，`requirement.tst` 不用于 pip。实际安装和精确版本由 `package-lock.json` 管理。首次安装需要能够连接 npm 镜像；安装后全部演示流程可本地运行。

## 测试与生产构建

```sh
npm test
npm run build
npm run preview -- --port 4173
```

- `npm test`：执行业务回归测试。
- `npm run build`：先检查 TypeScript，再生成 `dist/`。
- `npm run preview`：在 http://localhost:4173/ 检查生产构建，适合本地验收。

## 生产部署

本项目为纯静态网页，不需要数据库服务器或后端进程。

### 部署至 Nginx

1. 在开发机或构建机执行 `npm ci`、`npm run build`。
2. 将 `dist/` **里面的全部内容**复制到服务器，例如 `/var/www/homekeeper/`。
3. 参考 `deploy/nginx.conf.example` 配置根目录、域名与站点服务。
4. 启用站点后，用服务器自己的方式检查并重新加载 Nginx。正式对外使用建议配置 HTTPS。
5. 检查首页、`assets/` 静态资源及 `references/food-storage.xlsx` 均能加载。

也可将 `dist/` 内容上传至支持静态网页的托管平台。默认部署到站点根路径；如需部署在 `/homekeeper/` 等子路径，在 `vite.config.ts` 中配置相应 `base` 并重新构建，保留所有构建目录结构。

不要通过双击 `index.html` 的 `file://` 地址启动；请通过 HTTP/HTTPS 服务访问。`npm run dev` 和 `npm run preview` 用于开发与本地验证。

手机与电脑在同一网络时，可以访问 Vite 输出的 Network 地址；正式部署采用适合手机访问的 HTTPS 域名。手机布局已做 390px 视口验证，未进行实体手机兼容性测试。

## 功能

### 库存与家庭概览

24 条首次示例物品，覆盖正常、临期、今天到期、过期、未设置日期、低库存、已用完及同名不同批次。数据只在首次初始化或主动确认重置时生成。

支持名称搜索、类别/位置/状态筛选、到期时间排序、卡片/列表、新增、编辑、确认删除、消耗、补充和库存日志。数量支持小数，不能扣为负数。不同到期日期保持独立批次，位置为选填，未填写时显示“位置未设置”。

在库种类按有库存的名称去重；临期、低库存按批次计算。最低库存是各批次配置，新批次补货不会覆盖旧批次的数量和记录。

### 智能录入

支持中文自然语言、本地规则解析、批量可编辑预览。例如：

- 我今天买了3个苹果，2根香蕉
- 买了10个鸡蛋放冰箱冷藏室，还有2瓶洗衣液放阳台柜
- 买了3个苹果，2根香蕉，都放在冰箱冷藏室

支持逗号、顿号、连续数量、中文数量以及“还有”等表达。共享位置请明确说“都放在”。不确定的信息留空；未识别片段逐项提示，核对确认后才允许仅保存已识别项目。改写原输入会清除旧预览，避免保存过时解析。

### Excel 日期参考

使用提供的 6 张表、54 行参考原文。规则按食品、储存方式和状态匹配。混合单元格单独拆分，例如黄瓜与整冬瓜不共用同一天数。

- 范围按下限设置提醒，并展示完整范围与上限日期。
- 天、周、月分别处理；月按日历加月，月末取目标月有效日期。
- “当天吃完”为当天提醒，不视为没有规则。
- 未开封鲜奶、酸奶及常温盒装奶等选择生产日期；已开封食品选择开封日期；切开水果选择切开日期。
- 奶类、整鸡/鸡块等存在多种类型时，先让用户选择，不擅自判断。
- “冷藏更久”“不建议冷冻”等无明确数字的内容保留说明，不编造天数。
- 冷冻参考标注为品质规划参考，不能理解成安全到期保证。
- 估算日期带“预计”标记，并保留来源工作表、行号、原文、状态和起算日期。手动改写日期会移除估算标记，更改关键条件需重新估算。

参考表并非对所有品种、品牌与加工状态都适用；包装标识和实际状态优先。已有用户设置的日期不会因规则更新被重新覆盖。

### 食谱

共 **78 道**：保留原有 39 道，录入用户提供的 41 条内容，合并“番茄炒蛋/番茄炒鸡蛋”和“香菇炒鸡蛋”两个重复项。

支持全部浏览、推荐搭配、菜名/别名/食材搜索、5 种偏好、1—6 人份及用户提供的 6 类菜谱。新入库食材实时影响匹配，并展示关联理由。

保留步骤、原始量词和 tip，对容易把变质误作临期的提示修正措辞。盐“少许”、白菜“几片”等不捏造克数，单独展示为待确认用量；做菜确认时可填写实际数量与单位，未填写的项目不扣库存。

已量化的蒜瓣、勺、朵等按原单位校验；无法与库存单位换算时提示核对，不假装足量。克/千克/斤与毫升/升支持换算。西红柿/番茄、鲜香菇/香菇、香干/豆干等名称别名匹配，不因此推断未知单位换算率。

查看食谱不扣库存。确认实际用量后，只扣未过期批次，优先较早到期的批次；校验失败时不部分扣减。缺少的定量食材可加入采购，重复建议去重。

### 启动提醒、采购与助手

打开或刷新时，根据当前数据弹出一次家庭提醒：食品、饮料和调味品未来 3 天内到期（含今天）、已过期食品单独分组、所有类别低库存。无提醒不弹，切换页面不重复弹。

弹窗可查看物品、查看全部提醒、一键将低库存建议加入采购，支持稍后处理与今日不再提醒。设置页“查看当前家庭提醒”可手动打开；取消“今日不再提醒”并关闭可恢复当天启动提醒。免提醒只保存日期，不会修改库存。

采购项目支持手动编辑、建议去重、同名同单位手动合并；买到后确认实际数量、可选位置和日期，再作为新批次入库并完成采购项。

助手使用当前数据完成查询、寻物、临期、补货预览和食谱入口。数据修改先预览再确认，明确标注本地演示模式。

## 数据存储、升级和备份

- 库存、位置、采购与日志保存在当前浏览器 localStorage 的 `homekeeper.v1`。
- 今日免提醒日期保存在独立键 `homekeeper.reminder.hidden-date.v1`。
- 同一设备的不同浏览器、不同域名、不同端口分别存储，不自动同步。移动网站地址或清理站点数据会影响对应的数据可见性。
- 当前修改兼容已有记录，新增估算信息是可选字段，不需要重置。
- 存储损坏不静默覆盖原始数据，写入失败不提交库存修改。
- 对实际数据，可在浏览器开发工具的站点存储界面复制 `homekeeper.v1` 的完整 JSON 进行备份。恢复前先备份原数据，并保持 JSON 完整有效。
- “重置演示数据”会在确认后替换现有库存、位置、采购和日志，无法撤销。

## 更新参考表与源码打包

网页运行不需要 Python。只有维护人员重新提取 Excel 时才需要 Python 3 和 openpyxl：

```sh
python scripts/extract-reference.py public/references/food-storage.xlsx
```

提取脚本保留原文，不自动猜测复杂条件。表格结构或行号变化时，需要相应维护 `src/services/foodRules.ts`，然后执行测试和构建，确认全部参考行被覆盖。

发布前执行测试、构建后，可使用 Python 标准库打包：

```sh
python scripts/package-source.py
```

生成 `deliverables/homekeeper-complete-source.zip` 以及 `SHA256SUMS.txt`。不要在压缩包中加入 node_modules、密钥、浏览器真实数据或缓存。
